# Nexus V4 三车跨场景验证（2026-10-27）

目的：检查 scene033 上的改善能否迁移到其他 nuPlan 场景。冻结当前 V4 权重及推理优化参数，测试过程中不针对新场景调参，不修补采样后的轨迹。

输入与选样：

- 沿用独立256场景缓存及此前历史几何筛选结果；选样不读取新生成响应。
- 首批选定 015、050、060，来自不同日志，含左右切入、不同观测速度。
- 060 的地图 A 模板在输入预检中失败（正常 A 越出道路 39/80 点，最大位置加速度约19.11m/s²；事件约31.63m/s²）。保留证据，不将该错误算成 Nexus 响应失败。预检快照在 `artifacts/nexus_multiscene_preflight_v1_20261027/`。
- 在任何新场景模型生成前补入 018，固定实际生成 015、050、018，各 seed0、正常/事件两次，共六次。
- 015：E/A/C 原始 slot 0/12/26，事件车从右向左切入。
- 050：slot 0/17/11，事件车从左向右切入；A观测13.38m/s高于E的8.21m/s，可观察弱威胁下的过度反应。
- 018：slot 0/6/1，事件车从左向右切入，C为后方跟车。

方法与条件：

- 前2秒五个观测状态固定，仅按原方法从历史位置重建观测速度；历史位姿/朝向/尺寸不变。
- A 的未来8秒固定；正常 A 根据当前速度和 SDK 车道拓扑构造；事件 A 在0.5–2.5秒以五次曲线向自车侧横移3米。
- 新场景无 scene033 的 A 向前2米编辑。保留真实观察起点。
- E/C 未来条件掩码全假、条件值全零；其他已观测车辆未来也自由生成。地图初始化只来自当前状态与 SDK 路网。
- 每场正常/事件使用相同 seed0、初始噪声、地图控制初始化；所有未来自由控制可继续优化。
- 复用 `InitializedCruiseRefiner` 和 scene033 最终 V4 的完整配置，不训练、不改权重、不改默认升级文件。
- 为适应原 slot，新增通用角色验收入口；已在033正常/事件核对全部指标与旧验收器逐项完全一致。
- 车道 SDF 使用原 SDK 多边形栅格算法及0.1m分辨率，统一扩大覆盖至[-40,180]×[-90,90]m；道路 SDF 仍为0.25m。
- 背景和未来存在掩码沿用记录，属于显式额外信息，并非纯历史闭环仿真。

验收与解释：

- 0.1–8秒共80点有向车身碰撞、道路、原车道检查；车身尺寸来自观测，自车后轴转车体中心加1.461m。
- 原生0.5秒位置计算加速度、方向偏差、倒退、速度通道偏差；阈值与旧实验相同。
- 正常 E/C 需完整留在选定原车道；事件可合理换道。
- 独立初始车身审计发现050的C在历史终点已经跨出所选车道边界。该例仍保留，验收不放宽；解释初始短时越线时须展示该事实。
- 报告实际速度曲线和正常/事件差异，不将仅针对033设定的85%巡航阈值用于所有路口。不能仅凭低速或减速判定错误。
- 将正常预测 E 与事件 A 拼接做离线威胁检查；不把该 E 未来反馈为条件，也不把轨迹差异当成 E 导致 C 的严格因果链。
- 全部成功/失败都展示；不自动导出合格下游包。本轮结果是俯视运动视频，无新3DGS重建。
- 这是有选择的少量场景、单个随机种子验证，不能作为总体成功率或跨城市泛化结论。
