本轮针对“停车清楚、行驶后道路、建筑、天空和车辆一起出现重影”。结果目录为 `artifacts/nexus_3dgs/optimization_v6/`。这里的实验候选不等于全部修复；最终采用的结果和量化检查见该目录的交付清单。

**最终结论：两处代码问题已修复，但本轮静态重建候选未通过画质验收，没有替换 v5。整景运动重影仍未解决。**

## 已确认的现象

用 v5 保存的实际相机和车辆状态重放，未重新采样 Nexus 轨迹。新重放器在抽查帧与旧 PNG 的平均绝对误差小于 0.000006 个 8 位灰度级，最大误差为 1；扩展到 131 帧、四路相机后，共享帧也保持这个误差水平。

将运动拆成四组：相机和车辆均固定、仅相机运动、仅车辆运动、两者均运动。相机和车辆均固定时逐帧一致；相机运动而车辆固定时背景仍出现变形。再将相机运动拆成旋转和平移，旋转组与首帧按真实旋转重投影的图像达到约 44–46 dB；平移组出现明显重影。这支持优先检查三维几何与遮挡，不能单凭这个实验断言所有车辆表面都已正确。

原背景中，有 91,886 个高斯在多帧高置信度道路区域得到支持，但其中心距实测道路平面的高度绝对误差第 90 百分位约 0.52 米。高置信天空区域的有限深度高斯不透明度均值约 0.94，意味着部分天空也被写进了有深度的背景层。相机平移会使这些错误深度暴露出来。

记录视角质量需要逐帧看：v5 第 20、55 帧约 37 dB，第 70 帧只有约 21.6 dB。整段平均分会掩盖这段误差。把相机换成传感器标定加一个固定校正后，控制组反而下降，所以暂未采用这个相机替换，也不能把约 0.5° 的学习相机偏差直接认定为根因。

## 已修复的训练问题

`Omniscenegraph/models/modules.py` 的 `AffineTransform` 原来将嵌入、隐藏层和输出层权重全部置零。ReLU 特征和它的梯度因此无法启动，网络只能学习一个所有图像共用的偏置，无法正常学习逐图像颜色校正。

现在保留隐藏特征的正常初始化，仅将输出层置零，因此初始变换仍严格为单位变换。旧检查点加载时依旧覆盖所有权重，原视频不会因此自动变化。继续训练旧模型时，通过显式的 `revive_constant_features()` 保持当前颜色变换完全相同，再恢复可学习特征。

行为检查覆盖：所有图像初始变换严格为单位变换；相同 RGB 在两幅图中可以学到相反的曝光变化；旧模型载入和显式恢复特征前后变换完全一致；背景曝光改变时可以保持车辆的显示颜色。这个问题已证实，但不应把它说成全部几何重影的唯一原因。

另一个代码问题是：训练的高斯光栅化使用经过 `CamPose` 修正的相机，而环境天空仍使用原始方向射线。新增 `trainer.render.synchronize_sky_camera: true` 时，两者方向统一，射线对照行为测试通过。旧配置默认保持旧行为，避免直接改变旧检查点的环境层含义。此前生成相机的桥接代码已经会同步射线，本次修复针对训练时的学习相机路径，不应说成旧生成视频一直没有同步相机。

## 静态场景重新优化

从同一个 nuPlan 场景补充真实观测：131 帧、相机 `[0,1,2,4]`，共 524 张图像，包含原场景之后额外 3 秒的重建观测。原先共享的 101 帧相机参数、车辆模型及位姿在扩展时保留。额外观测只用于离线重建，不增加 Nexus 的预测条件，也不改变生成相机或车辆轨迹。

静态训练排除全部标注交通物体投影以及保守的附近阴影区域，包含没有模型的未来物体。真实点云提供深度监督，实测道路平面提供局部表面约束；天空/道路语义来自模型预测，含置信度和真实点云保护，不是人工真值。冻结车辆和相机参数，只训练静态背景、环境光和恢复学习能力的颜色校正。高斯索引固定，避免道路约束错绑到新高斯。

车辆仍使用原来的辐射颜色。若背景颜色校正改变，在原生高斯光栅化前进行颜色基变换；车辆几何、透明度和保存的球谐参数均不改动。其目的是防止重新优化背景曝光时连带改变车辆颜色。

实际完成 6,000 步静态几何训练与 4,000 步外观训练。后 4,000 步中背景位置、尺度、旋转与透明度逐项保持不变，仅优化颜色、环境光和曝光；见检查点旁的 `protected_parameters.json`。生成视频统一采用第 20 帧曝光，以免逐帧曝光学习带来新的时间闪烁；记录相机检查仍使用对应图像的曝光。

## 已尝试但不能当成最终修复的候选

| 实验 | 检查结论 |
| --- | --- |
| 直接压平道路高斯并重新拟合颜色 | 部分标线更清楚，但出现材质接缝，记录视角质量下降 |
| 用真实照片建立原生道路高斯层 | 减少部分道路叠影，但车辆周围仍有接缝和阴影问题 |
| 由真实点云建立局部背景高斯层 | 有些树木变清楚，但稀疏支撑和原层混合造成新的斑块 |
| 全局替换环境天空 | 损伤原来借助环境层表示的非天空细节 |
| 限定在多次真实天空观测方向替换天空 | 影响更局部，保留车辆区域；仍需完整视频检查，不能称为整景修复 |
| 传感器标定加固定相机校正 | 公平对照下质量下降，未采用 |

所有候选都保存在单独目录，未覆盖 v5。不能只挑标线局部变清楚的图片宣称整体修复。

## 主要代码和检查

- `nexus_3dgs/replay.py`：恢复实际刚体三维旋转、通用检查点载入、颜色基转换及可选原生场景层。
- `scripts/pipeline/replay_nexus_motion.py`：四组运动及旋转/平移对照，记录实际渲染状态。
- `scripts/pipeline/prepare_nexus_static_refinement.py`：静态训练排除掩码与实测道路约束。
- `scripts/pipeline/extend_nexus_static_checkpoint.py`：扩展真实观测、保留共享模型参数。
- `scripts/pipeline/train_nexus_static_scene.py`：冻结交通和相机的静态训练，结束后逐参数核验。
- `scripts/pipeline/check_nexus_replay.py` 与 `check_nexus_appearance.py`：重放刚体恢复和可学习颜色校正的行为检查。

旧 v1–v4 部分工作目录当前已不存在。本轮使用仍保留的 v5 检查点和实际状态，以及可用的原始 nuPlan 数据。重放不依赖已移除的旧预测包路径；状态来源和哈希写入每次渲染记录。

记录相机的 PSNR/SSIM 用于监测原有画质是否退化，不是生成视角的真实质量证明。基础模型已经见过原 101 帧；微调时排除部分帧，也不能把它们称为从未见过的独立测试集。

## 重放入口

在仓库根目录执行以下命令，会另建输出目录，不覆盖本轮对照结果：

```bash
V6="$PWD/artifacts/nexus_3dgs/optimization_v6"
bash scripts/pipeline/nexus_3dgs.sh script \
  "$PWD/scripts/pipeline/review_nexus_static_refinement.py" \
  --checkpoint "$V6/reconstruction/nuplan/static_radiance_25000/checkpoint_final.pth" \
  --source-root "$V6/source" --scene "$V6/source/original_scene" \
  --output "$V6/reproduce_final" --conditions go stop reference --full-video
```

重放只需保存的模型和实际状态，不需要重新运行 Nexus，也不需要恢复已删除的 v3 预测包。补充数据和训练配置保存在本轮目录，环境依赖没有安装或升级。
