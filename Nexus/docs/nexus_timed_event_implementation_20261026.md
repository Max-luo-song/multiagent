# 指定车辆与时段的事件条件生成

目标：接收事件 → 生成指定车辆的局部轨迹条件 → Nexus 联合生成自车及其他车辆 → 审计交互 → 3DGS 视频。

主流程允许 Nexus 自由生成自车未来。独立策略与 WorldEngine 的闭环评测是后续分支，不是本次视频生成的前置要求。

## 执行顺序

1. 核对现有场景、车辆身份、历史状态与已验收 v9 资产，选择有观测资产的事件车辆。原始预测和既有视频不覆盖。
2. 实现结构化事件协议：场景 token、车辆 track token、行为、开始与结束时间、行为参数、种子列表。支持局部匀速、急减速和横向靠近；事件轨迹仅使用历史与显式参数构造，不读取其他车辆未来。
3. 实现条件编译与推理：固定全部参与者历史，只固定指定车辆在请求时段的完整状态；自车与其他车未来全部自由。事件外的目标车辆未来也自由。0.5 秒时间网格上执行，非网格时间明确拒绝。所有未给定未来数值清零。
4. 运行配对验证：相同历史、地图、有效性与初始噪声，对比正常行驶片段和事件片段。预先固定少量种子，全部保留，不能把一个有利样本当总体结论。核对条件精确保留、输入不泄漏未来、权重未变及输出完整。
5. 分层审计：事件执行情况；物理尺寸的车框重叠、速度／加速度与朝向；自车响应和其他车响应。轨迹差异只表示条件敏感性，不能证明“目标车→自车→第三辆车”的因果链。所有第三辆车也直接看得到事件条件。
6. 用既有 v9 高斯资产渲染预先指定种子的对照与事件两段视频；左侧俯视图标记车辆，右侧高斯画面不叠加编号。生成可在 VS Code 中预览的 HTML 报告，列出全部种子与失败原因。

## 首轮边界与验收

- 使用现有一例已验收重建场景，不重新训练 Nexus 或重建资产。
- 事件只是数值轨迹条件，当前不实现自由自然语言理解。上游 Agent 可输出协议 JSON。
- 仅对历史中已存在且完成身份绑定的非自车对象施加事件，不新增无资产车辆。
- 急刹、靠近是连续动作，使用时间段而非孤立点。单时刻状态接口可接受关键帧条件，但不能据此声称已定义完整动作。
- 原生时间分辨率为 0.5 秒，未来 8 秒；视频使用实际相机曝光时刻插值，另行审计实际车体安装后的重叠。
- 未来有效性沿用数据记录中的存在 mask，必须在报告说明；这不是完全不使用未来信息的部署预测实验。
- Nexus 整段联合生成，可能在事件开始前表现出条件差异；不能宣称在线触发后的严格因果响应。
- 技术验收：事件配置可复现、局部 mask 正确、自车未来无固定值、条件值精确保留、配对噪声一致、所有有效状态有限且可导出。
- 行为验收独立记录：危险行为成立、自车自由响应合理、第三车出现相关交互、无无关穿车。未通过则输出失败诊断视频，不能用后处理修改轨迹冒充模型生成成功。

## 输出

`artifacts/nexus_3dgs/timed_event_20261026/`：事件请求、编译条件、原始 PT、轨迹包、全部种子审计、渲染、视频和进度。

`report/nexus_timed_event_20261026.html`：输入条件、生成行为、限制、配对视频和验收结果。

## 重复运行入口

使用 Nexus 环境的 Python 执行 `scripts/pipeline/run_nexus_timed_event.py --request <事件 JSON> --output <全新结果目录>`。请求示例为 `artifacts/nexus_3dgs/timed_event_20261026/event_request.json`；输出目录必须不存在，以保护既有结果。

请求字段为 `schema_version=1`、`source_run`、`scenario_token`、`actor_track_token`、`behavior`、`start_s`、`end_s`、`parameters`、`seeds`、`render_seed`。当前窗口端点均计入条件。

行为参数：`reverse_approach` 使用正数 `distance_m`，要求历史近乎停止；`lateral_shift` 使用 `distance_m` 与 `side=left/right`，要求历史速度至少 1 m/s；`brake` 使用正数 `deceleration_mps2`，要求历史速度至少 1 m/s。横向移动不自动解释为合法变道，仍需道路／车道审计。

编译器不读取未来数值；存在 mask、地图来源及条件轨迹之外的道路合规性均应独立审查。倒车事件已做真实模型与视频验证，横向移动／制动目前只通过数值编译检查。
