# nuPlan 定量评测流程与边界

本阶段从单场景演示进入官方验证集上的小规模指标试跑。试跑用于检查
模型验证分支、预处理、指标聚合和结果留档，不能代表全验证集或论文成绩。

## 入口与数据

`scripts/pipeline/run_nuplan_metrics.py` 使用官方 nuPlan splitter 的 `val` 日志
清单，与共享 `plan_data/val` 取交集。本机交集为 1,381 个数据库。
默认只使用按文件名排序的前两个数据库，挑选 8 个唯一场景；这是一组便利
样本，不是具有代表性的随机抽样。场景须有至少 2 秒历史和 8 秒未来可读取。
实际 token、日志名、类型、时间戳及选择方法记录在每次运行的 `run.json`。

该入口不创建优化器，不进行训练更新。模型以 `eval()` 和
`torch.inference_mode()` 执行官方 `forward_validation`，最后检查参数版本
计数未变化。官方 bash 入口采用“先训练一步再验证”的流程，本地入口直接
执行验证以保持加载后的预训练参数。

模型与特征构建采用 `config/common/model/nexus.yaml`，调用正式
`NexusFeatureBuilder.get_features_from_scenario`，并执行验证配置中的
`ResetVAugmentor`。它不同于之前的演示 helper：车辆数量、地图要素和地图
折线数量使用正式模型配置，保留原实现的速度通道预处理。本阶段不另行修改
预处理的算法含义。

默认约束配置与 `scripts/testing/test_nexus_metrics.sh` 一致：
`map, sma, clip`，强度各为 1.0，32 步 `full_sequence` 日程。
此处所有车辆的历史已知，因此沿用原始日程，不启用场景补全演示中的
`--denoise-history` 或固定自车未来的修改。

## 两种验证任务

- `behavior_pred`：已知所有车辆过去 2 秒及当前状态，生成未来 8 秒。
- `intent_conditioned_behavior_pred`：在上述历史条件之外，给定各车辆最后
  一个有效时刻的真实状态，再生成其余未来状态。终点属于输入条件，终点
  误差小不能解释为模型独立预测终点的能力。

论文的 free exploration 与 conditioned generation 定义可参见
[附录 D.2](https://arxiv.org/html/2504.10485v1#A4.SS2)。

## 官方指标实现及解释

评测直接实例化 `testing_nuplan_nexus` 中四组 aggregated_metric 配置，未重写
这些指标公式。需注意以下实现细节：

1. `BehaviorPredictionMetric` 默认排除自车，在未来 1、2、…、8 秒分别计算
   有效车辆的平均位置误差。`displacement@avg_8s` 是八个整秒误差的算术均值，
   `avg_7s` 是前七个整秒误差均值。它们应使用原名报告，不能直接混称所有
   0.5 秒采样点上的标准 ADE。部分短轨迹的给定终点可能早于 8 秒，公式并未
   进一步排除这些终点。
2. `CollisionMetric` 实际以碰撞车辆对计数，再除以有效车辆数。它与按发生
   碰撞的不同车辆计数的定义存在差异；报告称为“代码碰撞计数比”，不冒充
   论文完全一致的碰撞率。
3. `TrajMetric` 的越界代理指标采用到地图采样点的距离阈值 2.75 米，以所有
   有效车辆为分母。它不是直接对可行驶区域多边形进行判断。道路指标的
   源码文档字符串和实际分母存在差异，记录以实际实现为准。
4. 官方时间字段没有完整 GPU 同步。另行记录同步后的两种任务总耗时，
   不将它与论文运行时间直接比较。

论文指标定义见[附录 D.1](https://arxiv.org/html/2504.10485v1#A4.SS1)。
当前代码实现与论文描述的差异需要在正式论文数值对齐前处理。

## 避免指标间的数据污染

`BehaviorPredictionMetric.update` 会通过张量视图原地清除自车有效性；
`TrajMetric.update` 会原地将地图坐标反归一化。多个指标直接共享预测字典时，
后续指标可能接收到被改写的有效性掩码或重复反归一化的地图。

本地入口为每个官方指标提供独立的 CPU 数据副本，并检查原始有效性掩码和
地图张量保持不变。指标内部公式保持原样。这是与直接依次更新共享字典的
上游流程之间的显式适配，应保留在复现实验记录中。

## 运行

在恢复既有环境后，从 Nexus 仓库运行：

```bash
python -u scripts/pipeline/run_nuplan_metrics.py \
  --num-scenarios 8 --num-dbs 2 --seed 0 --constraints official
```

输出保存到新的 `artifacts/nuplan_metrics/val_pilot_<timestamp>/`：

- `run.json`：数据选择、场景清单、源码哈希和逐场景进度。
- `config.yaml`：实际模型、数据与约束配置。
- `prediction_*.pt`：每个场景的两类预测、GT、有效性和地图。
- `metrics.json`：官方聚合指标结果。
- `metric_states.json`：指标累积状态及分母。

只有所有指定场景和有限值检查通过、聚合指标完整保存后，才写入
`status=complete` 并输出 `NUPLAN_METRICS_PILOT_OK`。依赖从共享存储加载较慢时，
首次初始化可能需要数分钟。

## 已完成的试跑与速度预处理对照

2026-10-20，`val_pilot_20261020_140122_172964` 完成 8 个唯一场景，实际覆盖
两个官方验证日志。原始配置的普通预测整秒误差均值为 14.3333 米；给定终点
任务前七个整秒均值为 4.9500 米。

`run_nuplan_preprocessing_control.py` 对相同场景比较官方 ResetV 和保留原始
速度两个分支。每场景恢复相同 CPU/CUDA RNG 状态，验证消耗后 RNG 也相同，
并核对场景位置、朝向、地图和有效性。官方分支除计时外的聚合指标与首次
试跑逐值一致。

对照结果位于 `preprocessing_control_20261020_142405_096637`：

| 诊断项 | 官方 ResetV | 原始速度 |
| --- | --- | --- |
| 普通预测整秒误差均值（米） | 14.3333 | 7.5204 |
| 给定终点前七个整秒误差均值（米） | 4.9500 | 2.8811 |
| 普通预测代码碰撞计数比 × 100 | 2.3604 | 2.8784 |
| 给定终点代码碰撞计数比 × 100 | 2.7956 | 3.6731 |

在 347 个有效非自车历史状态对上，原始速度与位置差分参考的平均向量差
为 0.2470 米/秒，ResetV 后通道为 3.3832 米/秒。这支持当前处理改变了速度
通道的运动含义，但尚未确定权重训练时所用的预处理。

位移误差改善不代表全部指标改善，因此没有修改官方 ResetVAugmentor，也
没有将诊断分支作为默认官方评测配置。可用以下命令复运行该对照：

```bash
python -u scripts/pipeline/run_nuplan_preprocessing_control.py \
  --reference-run artifacts/nuplan_metrics/val_pilot_20261020_140122_172964
```

对照同时保存了原始特征，供后续检查复用，避免重复读取数据库。

## 约束敏感性对照

`run_nuplan_constraint_control.py` 固定上述原始速度特征和随机噪声，比较
三组设置：`map,sma,clip` 强度 `[1,1,1]`；强度 `[0.1,0.1,1]`；仅 `clip`。
第三组对应模型构造器默认约束，第一组对应官方测试脚本。中间一组仅用于
诊断强度敏感性，不声称是论文设置。

该实验不会根据最低误差覆盖官方结果。每个分支的所有指标和预测独立保存，
用于确定扩大评测前需要固定哪些配置。
